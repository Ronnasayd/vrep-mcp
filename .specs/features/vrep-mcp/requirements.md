## 1. Inicialização e carga do catálogo

O servidor sobe sem tocar no simulador nem no modelo de busca. O catálogo vem dos arquivos JSON processados da documentação.

| Requiriment | Scenario                                  | Expression                                                                                                                                                                                                                   | Complement                                                                                                                                          | Path |
| ----------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| NR-001      | Servidor inicia                           | **Given** o servidor acabou de subir **When** nenhuma ferramenta foi chamada **Then** nenhuma conexão com o simulador é aberta **And** o modelo de embeddings não é carregado                                                | O cliente MCP sobe o servidor junto com a sessão; abrir rede ou baixar modelo nessa hora atrasaria toda sessão, mesmo as que nunca usam o simulador | SP   |
| FR-001      | Catálogo carregado no primeiro uso        | **Given** os 5 arquivos de catálogo existem e são JSON válido **When** uma ferramenta precisa do catálogo **Then** todas as funções e constantes ficam disponíveis por nome no formato `namespace.metodo`                    | Um nome único e qualificado evita ambiguidade entre namespaces e é o que o agente passa adiante                                                     | SP   |
| FR-002      | Arquivo de catálogo ausente ou corrompido | **Given** um arquivo de catálogo falta ou não é JSON válido **When** uma ferramenta precisa do catálogo **Then** a ferramenta devolve erro com o caminho do arquivo e o motivo **And** nenhum resultado parcial é devolvido  | Um catálogo pela metade faria o agente concluir que funções existentes não existem                                                                  | EP   |
| FR-003      | Diretório de dados configurável           | **Given** a variável de diretório de dados está definida **When** o catálogo é carregado **Then** os arquivos são lidos desse diretório **And** sem a variável, são lidos de `processed/` na raiz do projeto                 | Permite atualizar a documentação processada sem editar o pacote                                                                                     | SP   |
| FR-004      | Constantes sem prefixo                    | **Given** uma constante do arquivo de constantes não traz namespace **When** o catálogo é montado **Then** ela é registrada no namespace `sim`                                                                               | O arquivo de constantes não tem prefixo e todos os nomes correspondem a constantes de `sim`; premissa não confirmada pelo usuário                   | SP   |
| FR-005      | Listar namespaces                         | **Given** o catálogo está carregado **When** o agente pede a lista de namespaces **Then** recebe os 4 namespaces em ordem fixa (`sim`, `simUI`, `simROS2`, `simVision`), cada um com sua contagem de funções e de constantes | É o ponto de partida barato para o agente entender o tamanho da API antes de buscar                                                                 | SP   |

## 2. Busca semântica

| Requiriment | Scenario                               | Expression                                                                                                                                                                                                                                                                                      | Complement                                                                                            | Path |
| ----------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ---- |
| FR-006      | Busca básica                           | **Given** uma consulta não vazia **When** o agente busca **Then** recebe no máximo o número pedido de resultados (padrão 10), ordenados do mais para o menos similar **And** cada resultado traz nome, tipo (função ou constante), namespace, descrição de até 200 caracteres e nota de 0 a 100 | Descrição curta e nota deixam o agente escolher sem carregar o schema de cada candidato               | SP   |
| FR-007      | Filtro por namespace                   | **Given** a busca informa um namespace válido **When** o agente busca **Then** só voltam itens desse namespace **And** itens de outros namespaces são excluídos mesmo que mais similares                                                                                                        | Evita confundir funções de mesmo propósito em plugins diferentes (ex.: UI vs. núcleo)                 | SP   |
| FR-008      | Filtro por tipo                        | **Given** a busca informa o tipo "função" ou "constante" **When** o agente busca **Then** só voltam itens desse tipo **And** itens do outro tipo são excluídos                                                                                                                                  | As 399 constantes dividem o índice com as funções; o filtro impede que elas tirem funções do topo     | SP   |
| NR-002      | Consulta em inglês                     | **Given** uma consulta em inglês que descreve o propósito de uma função **When** o agente busca **Then** essa função aparece entre os 5 primeiros resultados                                                                                                                                    | Medida objetiva de que a busca funciona para o caso comum                                             | SP   |
| NR-003      | Consulta em português                  | **Given** uma consulta em português que descreve o propósito de uma função documentada em inglês **When** o agente busca **Then** essa função aparece entre os 5 primeiros resultados                                                                                                           | O usuário escreve em português; por isso o modelo escolhido é multilíngue                             | SP   |
| FR-009      | Primeira busca constrói o índice       | **Given** não existe cache de índice para o conteúdo atual do catálogo **When** a primeira busca acontece **Then** todas as entradas são vetorizadas **And** o índice é salvo em disco com nome derivado do hash do catálogo                                                                    | A construção só acontece quando alguém busca, então sessões que não buscam continuam iniciando rápido | SP   |
| FR-010      | Buscas seguintes reaproveitam o índice | **Given** existe cache de índice com o mesmo hash do catálogo **When** uma busca acontece em uma nova execução do servidor **Then** o índice é lido do disco **And** só a consulta é vetorizada                                                                                                 | Vetorizar ~975 itens a cada início desperdiçaria segundos por sessão                                  | SP   |
| FR-011      | Catálogo alterado invalida o índice    | **Given** o conteúdo de qualquer arquivo do catálogo mudou **When** a próxima busca acontece **Then** um novo índice é construído **And** o índice antigo não é usado                                                                                                                           | O hash no nome do arquivo garante que posições do índice nunca fiquem desalinhadas com o catálogo     | SP   |
| FR-012      | Consulta vazia                         | **Given** a consulta está vazia ou só tem espaços **When** o agente busca **Then** recebe erro dizendo que a consulta não pode ser vazia                                                                                                                                                        | Uma consulta vazia devolveria resultados arbitrários que pareceriam relevantes                        | EP   |
| FR-013      | Limite de resultados fora da faixa     | **Given** o número de resultados pedido é menor que 1 ou maior que 50 **When** o agente busca **Then** recebe erro informando a faixa válida (1 a 50)                                                                                                                                           | Limita o custo de tokens da resposta                                                                  | EP   |
| FR-014      | Namespace inválido na busca            | **Given** o namespace informado não é um dos 4 conhecidos **When** o agente busca **Then** recebe erro listando os namespaces válidos                                                                                                                                                           | Um filtro inválido que devolvesse lista vazia seria confundido com "nada encontrado"                  | EP   |
| FR-015      | Tipo inválido na busca                 | **Given** o tipo informado não é "função" nem "constante" **When** o agente busca **Then** recebe erro listando os dois valores válidos                                                                                                                                                         | Um filtro inválido que devolvesse lista vazia seria confundido com "nada encontrado"                  | EP   |
| FR-016      | Falha ao obter o modelo                | **Given** o modelo de embeddings não pode ser baixado ou carregado **When** o agente busca **Then** recebe erro dizendo que o índice de busca está indisponível e o motivo **And** as outras 3 ferramentas continuam funcionando                                                                | O agente ainda consegue usar a API se souber o nome da função                                         | EP   |

## 3. Schema de uma função

| Requiriment | Scenario                            | Expression                                                                                                                                                                                                                                        | Complement                                                                                                              | Path |
| ----------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---- |
| FR-017      | Schema de função                    | **Given** o nome de uma função existente **When** o agente pede o schema **Then** recebe nome, tipo, namespace, assinatura, descrição, link da documentação, retornos e um JSON Schema dos argumentos com as propriedades na ordem dos parâmetros | O agente monta argumentos válidos sem ler a documentação inteira; a ordem importa porque a chamada é posicional         | SP   |
| FR-018      | Parâmetros obrigatórios             | **Given** uma função cuja assinatura define valor padrão para alguns parâmetros **When** o schema é montado **Then** só os parâmetros sem valor padrão aparecem como obrigatórios **And** os que têm valor padrão aparecem como opcionais         | A presença de `nome =` na assinatura é o único sinal de opcionalidade nos dados                                         | SP   |
| FR-019      | Tipos básicos                       | **Given** um parâmetro de tipo inteiro, real, texto, booleano, lista ou dicionário **When** o schema é montado **Then** o parâmetro recebe o tipo JSON correspondente **And** o tipo original da documentação é preservado num campo à parte      | Tipos JSON permitem validar antes de chamar o simulador; o tipo original ajuda o agente quando o JSON é genérico demais | SP   |
| FR-020      | Tipos sem equivalente JSON          | **Given** um parâmetro de tipo sem equivalente JSON seguro (buffer, bytes, any, estruturas próprias) **When** o schema é montado **Then** o parâmetro não recebe restrição de tipo **And** o tipo original da documentação é preservado           | Um tipo inventado rejeitaria chamadas válidas                                                                           | SP   |
| FR-021      | Descrição de parâmetros alinhada    | **Given** a documentação de uma função tem uma descrição por parâmetro **When** o schema é montado **Then** cada parâmetro recebe sua descrição                                                                                                   | Ajuda o agente a escolher valores corretos                                                                              | SP   |
| FR-022      | Descrição de parâmetros desalinhada | **Given** a quantidade de descrições difere da quantidade de parâmetros **When** o schema é montado **Then** nenhum parâmetro dessa função recebe descrição                                                                                       | Parear listas desalinhadas atribuiria a descrição de um parâmetro a outro, o que é pior que não ter descrição           | SP   |
| FR-023      | Função sem assinatura Python        | **Given** uma função cuja documentação só traz assinatura Lua **When** o schema é montado **Then** parâmetros, obrigatoriedade e assinatura vêm da versão Lua                                                                                     | Lua e Python compartilham a ordem dos parâmetros; é o único dado disponível                                             | SP   |
| FR-024      | Schema de constante                 | **Given** o nome de uma constante existente **When** o agente pede o schema **Then** recebe nome, tipo "constante", namespace e o tipo do valor                                                                                                   | Constantes não têm argumentos; o agente só precisa saber que existem e o tipo                                           | SP   |
| FR-025      | Nome inexistente no schema          | **Given** um nome que não está no catálogo **When** o agente pede o schema **Then** recebe erro dizendo que a função é desconhecida e sugerindo usar a busca                                                                                      | Aponta o próximo passo em vez de só falhar                                                                              | EP   |

## 4. Validação dos argumentos (antes de contatar o simulador)

| Requiriment | Scenario                                            | Expression                                                                                                                                                                                                                                                                                                    | Complement                                                                                                                   | Path |
| ----------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---- |
| FR-026      | Mapeamento para chamada posicional                  | **Given** argumentos nomeados válidos **When** a chamada é preparada **Then** os valores são ordenados conforme os parâmetros do schema **And** a lista termina no último argumento informado                                                                                                                 | A API remota é posicional; omitir só o final deixa o simulador usar seus próprios padrões                                    | SP   |
| FR-027      | Função sem parâmetros obrigatórios e sem argumentos | **Given** uma função sem parâmetros obrigatórios **When** o agente chama sem argumentos **Then** a função é chamada sem nenhum argumento                                                                                                                                                                      | Caso comum (ex.: consultar estado da simulação)                                                                              | SP   |
| FR-028      | Argumento obrigatório faltando                      | **Given** um parâmetro obrigatório não foi informado **When** o agente chama a função **Then** recebe erro listando os obrigatórios ausentes **And** o simulador não é contatado                                                                                                                              | Falha rápida com mensagem clara em vez de um erro críptico do simulador                                                      | EP   |
| FR-029      | Argumento desconhecido                              | **Given** um argumento com nome que não é parâmetro da função **When** o agente chama a função **Then** recebe erro listando os nomes desconhecidos e os parâmetros esperados **And** o simulador não é contatado                                                                                             | Pega erros de digitação que de outra forma seriam ignorados em silêncio                                                      | EP   |
| FR-030      | Opcional pulado antes de um informado               | **Given** um parâmetro opcional foi omitido mas um parâmetro posterior foi informado **When** o agente chama a função **Then** recebe erro dizendo quais opcionais precisam ser informados **And** o simulador não é contatado                                                                                | Numa chamada posicional não dá para pular uma posição; o servidor não conhece os padrões reais do simulador para preenchê-la | EP   |
| FR-031      | Tipo de argumento incorreto                         | **Given** o valor de um argumento não corresponde ao tipo JSON do parâmetro **When** o agente chama a função **Then** recebe erro com o nome do argumento, o tipo esperado e o tipo recebido **And** inteiros são aceitos onde se espera real **And** booleanos são rejeitados onde se espera inteiro ou real | Em Python, booleano é inteiro; sem essa regra `true` passaria como `1` em silêncio                                           | EP   |
| FR-032      | Nome inexistente na chamada                         | **Given** um nome que não está no catálogo **When** o agente chama a função **Then** recebe erro dizendo que a função é desconhecida e sugerindo usar a busca **And** o simulador não é contatado                                                                                                             | Mesma mensagem usada ao pedir o schema, para o agente reagir do mesmo jeito: buscar o nome certo                             | EP   |

## 5. Execução no simulador

| Requiriment | Scenario                              | Expression                                                                                                                                                                                                                                                                 | Complement                                                                                                           | Path |
| ----------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---- |
| FR-033      | Chamada bem-sucedida                  | **Given** argumentos válidos e o simulador acessível **When** o agente chama a função **Then** a função correspondente do namespace é executada no simulador **And** o valor retornado é devolvido ao agente                                                               | Objetivo central: qualquer função da API acessível por uma única ferramenta                                          | SP   |
| FR-034      | Conversão do retorno                  | **Given** a função retorna tuplas, bytes, nulo ou objetos sem representação JSON **When** o resultado é devolvido **Then** tuplas viram listas, bytes viram texto base64, nulo vira `null` **And** outros objetos viram sua representação textual                          | O protocolo MCP só transporta JSON; base64 preserva bytes de imagens e buffers sem perda                             | SP   |
| FR-035      | Leitura de constante                  | **Given** o nome de uma constante **When** o agente chama a ferramenta de execução **Then** recebe o valor da constante lido do simulador conectado **And** argumentos enviados são ignorados                                                                              | O valor real vem do simulador; o catálogo só conhece nome e tipo                                                     | SP   |
| FR-036      | Simulador inacessível ou lento        | **Given** o simulador não responde dentro do tempo limite (padrão 30 s, configurável) **When** o agente chama uma função **Then** recebe erro com host, porta e tempo limite, orientando a iniciar o CoppeliaSim com o add-on de API remota **And** a conexão é descartada | O cliente oficial espera para sempre; sem limite o servidor inteiro travaria                                         | EP   |
| FR-037      | Reconexão após falha                  | **Given** a conexão anterior foi descartada por tempo limite **When** o agente faz nova chamada **Then** uma nova conexão é aberta                                                                                                                                         | Após uma resposta perdida, o socket do cliente fica inutilizável; reconectar permite seguir sem reiniciar o servidor | SP   |
| FR-038      | Erro devolvido pelo simulador         | **Given** o simulador rejeita a chamada com erro **When** o agente chama a função **Then** recebe erro com o nome da função e a mensagem original do simulador                                                                                                             | A mensagem original diz ao agente o que corrigir (ex.: handle inválido)                                              | EP   |
| FR-039      | Função ausente na versão do simulador | **Given** a função existe no catálogo mas não na versão do CoppeliaSim conectada **When** o agente chama a função **Then** recebe erro dizendo que a função não está disponível no simulador conectado                                                                     | O catálogo vem da documentação mais recente; versões antigas podem não ter todas as funções                          | EP   |
| NR-004      | Chamadas simultâneas                  | **Given** uma chamada está em andamento **When** outra chamada chega **Then** a segunda espera a primeira terminar                                                                                                                                                         | O canal com o simulador só suporta uma requisição por vez; intercalar corromperia as respostas                       | SP   |
| NR-005      | Conexão configurável                  | **Given** as variáveis de host, porta e tempo limite **When** a conexão é aberta **Then** esses valores são usados **And** sem elas valem `localhost`, a porta padrão da API remota (23000) e 30 s                                                                         | Permite simulador em outra máquina e chamadas longas (carregar cena, avançar passos)                                 | SP   |

## 6. Operação do servidor

| Requiriment | Scenario                        | Expression                                                                                                                                                                                                                              | Complement                                                                | Path |
| ----------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ---- |
| FR-040      | Ferramentas expostas            | **Given** o servidor iniciado pelo comando do pacote **When** o cliente MCP lista as ferramentas **Then** vê exatamente 4: listar namespaces, buscar funções, obter schema e chamar função                                              | Toda a API em 4 ferramentas mantém o custo de schema por requisição baixo | SP   |
| NR-006      | Saída padrão limpa              | **Given** o servidor roda via stdio **When** qualquer componente registra log, inclusive o cliente do simulador em modo verboso **Then** o log vai só para a saída de erro **And** a saída padrão carrega apenas mensagens do protocolo | Qualquer byte extra na saída padrão quebra a sessão MCP                   | SP   |
| NR-007      | Tamanho da lista de ferramentas | **Given** o cliente MCP lista as ferramentas **When** a resposta é medida **Then** ela tem menos de 2.000 tokens                                                                                                                        | É o ganho que justifica o servidor frente a expor ~975 ferramentas        | SP   |

## 7. Consequências aceitas — Accepted consequences (não são defeitos)

Comportamentos corretos linha a linha que, juntos, têm custo. Foram aceitos de propósito.

| #   | Consequence                                                                                                                                                                                  | Driven by              |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 1   | Qualquer função pode ser executada, inclusive as destrutivas (fechar o simulador, remover objetos, sobrescrever cena, executar script arbitrário). Não há confirmação nem lista de bloqueio. | FR-033, FR-040         |
| 2   | A primeira busca de cada máquina baixa o modelo de embeddings (centenas de MB, tamanho não medido) e vetoriza as ~975 entradas. Sem internet nessa hora, a busca fica indisponível.          | FR-009, FR-016, NR-001 |
| 3   | Com o simulador desligado, cada chamada leva até 30 s para falhar (padrão de tempo limite).                                                                                                  | FR-036, NR-005         |
| 4   | Uma chamada legítima mais longa que o tempo limite é tratada como falha e a conexão é descartada, mesmo que o simulador ainda esteja trabalhando.                                            | FR-036, FR-037         |
| 5   | Tipos vêm da documentação, não do simulador. Uma documentação imprecisa pode rejeitar chamadas válidas (tipos básicos) ou deixar passar valores inválidos (tipos sem restrição).             | FR-019, FR-020, FR-031 |
| 6   | 123 funções de `sim` ficam sem descrição por parâmetro porque a documentação está desalinhada.                                                                                               | FR-022                 |
| 7   | 14 funções de `sim` usam a assinatura Lua; se Lua e Python divergirem em ordem ou padrões, o schema estará errado para elas.                                                                 | FR-023                 |
| 8   | Para informar um opcional tardio, o agente precisa repetir todos os opcionais anteriores, porque o servidor não sabe preencher os padrões do simulador.                                      | FR-026, FR-030         |
| 9   | Parâmetros de callback (`func`, 10 ocorrências) não funcionam pela API remota.                                                                                                               | FR-020, FR-033         |
| 10  | Índices antigos ficam no disco quando o catálogo muda; não há limpeza automática.                                                                                                            | FR-011                 |
| 11  | Toda constante é atribuída a `sim`; se alguma pertencer a outro namespace, a leitura falhará.                                                                                                | FR-004, FR-035         |
| 12  | Chamadas são serializadas: uma chamada lenta bloqueia todas as outras, inclusive leituras rápidas.                                                                                           | NR-004                 |

## Glossary

- **FR** — requisito funcional
- **NR** — requisito não funcional
- **SP** — caminho de sucesso
- **EP** — caminho de erro
- **MCP** — Model Context Protocol, protocolo entre o agente (LLM) e o servidor de ferramentas
- **stdio** — transporte em que o servidor conversa pela entrada e saída padrão do processo
- **Embeddings** — vetores numéricos que representam o significado de um texto; a busca compara a consulta com cada função por similaridade desses vetores
- **Namespace** — grupo de funções da API do CoppeliaSim (`sim`, `simUI`, `simROS2`, `simVision`)
- **API remota ZMQ** — interface oficial do CoppeliaSim para chamar funções de fora do simulador
